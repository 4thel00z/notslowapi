Same code. Fewer microseconds.

notslowapi is a fork of FastAPI made faster, measured layer by layer. Change one import and keep your app, your tests and your team. On one core, a plain JSON route serves 114,000 requests a second under granian against 32,000 for FastAPI 0.141 on uvicorn: 3.6x the throughput.

Switch in a minute.

Day one. No route, model or dependency changes; your test suite is the acceptance test.

1

Install

uv add notslowapi[granian]

One package. The granian extra pulls in the server you will run under.

2

Change the import

from notslowapi import FastAPI

Same class, same decorators, same dependency injection. Routers, models and middleware stay as they are.

3

Run under granian

granian --interface asgi --workers 1 --loop uvloop myapp:app

Staying on uvicorn also works; the deploy notes below cover the flags.

4

Done

pytest

Run your tests. FastAPI's own 4,489 pass against notslowapi; yours are the proof for your app.

What changed inside.

No new language. The request path does less.

Parameter extraction

Stopped introspecting type annotations on every request. The shape of an endpoint is known once, at startup.

Dependency solver

Skips work no endpoint asked for: the throwaway Response object, unused query and cookie parsing.

Exit stacks and middleware

Per-request exit stacks and middleware layers exist only when a route needs them.

Routing

Routes reached via include_router are matched once, not twice, and static paths are indexed.

Exception handling

One layer instead of three, and one frame from router to handler.

Encoding and parsing

Direct JSON encoding and query-string parsing, without the stdlib wrapper layers in between.

How the numbers were taken

Every change was measured before and after on a ladder of ASGI rungs, with native sampling from sample(1) and pyinstrument. Runs alternate after, before, after to reject noise. The numbers and the profiles are committed under bench/baseline, so you can rerun them.

Limits

These are single-core numbers. Multi-core scaling needs a separate client machine and is not measured yet. Code that imports starlette.* directly gets upstream Starlette, not the vendored, tuned copy.

Deploy.

Pick one server and pass the right flags.

Use granian

granian --interface asgi --workers 1 --loop uvloop myapp:app

The numbers above were taken with this line. Scale workers to your cores; the per-core figure is what changes.

If you stay on uvicorn

uvicorn myapp:app --no-proxy-headers --no-server-header --no-date-header

Pass these three flags. Without them uvicorn adds work to every response that the granian line above does not.

Questions.

Three that come up first. Open an issue on GitHub for the rest.

Is it really drop-in?
Yes. The API is FastAPI's and FastAPI's own 4,489 tests pass unchanged. You change one import. The one edge: notslowapi vendors and tunes Starlette, and nothing is installed under the starlette name, so code that imports starlette.* directly still gets upstream Starlette.
Where do the numbers come from?
One core of an Apple M3 Pro, Python 3.13, 64 keep-alive connections, the median of three 5-second runs, alternated after/before/after against FastAPI 0.141 on uvicorn. Profiles come from sample(1) and pyinstrument. Everything is committed under bench/baseline in the repository.
What about more than one core?
Not measured yet. Multi-core scaling needs a separate client machine so the load generator does not compete with the server. Everything published is a single-core number; treat it as the per-worker figure.
