How it got faster.

Six changes, each measured before and after.

Underneath, Starlette itself is vendored and tuned. Nothing is installed under the starlette name.

No. 1

Routes are matched once.

Routes reached via include_router are matched once, not twice, and static paths are indexed.

No. 2

Layers exist only when a route needs them.

Per-request exit stacks and middleware layers are created only when a route needs them.

No. 3

One exception layer, one frame.

One exception-handling layer instead of three, and one frame from router to handler.

No. 4

Parameters without introspection.

Parameter extraction stopped introspecting type annotations on every request.

No. 5

The solver skips work nobody asked for.

The dependency solver skips work no endpoint asked for: the throwaway Response, unused query and cookie parsing.

No. 6

Direct encoding and parsing.

JSON encoding and query-string parsing go direct, without stdlib wrapper layers.

Every number has a before and an after.

Every change was measured before and after, on a ladder of ASGI rungs.

Switch in a minute.

Three steps. The third one is where the granian numbers come from.

1

Install

uv add notslowapi[granian]

Pulls notslowapi with the granian extra from PyPI.

2

Change the import

from notslowapi import FastAPI

Everything else stays as it is. The same 4,489 tests pass.

3

Serve

granian --interface asgi --workers 1 --loop uvloop myapp:app

One worker, uvloop as the event loop.

Deploy on granian.

Use granian. If you stay on uvicorn, pass --no-proxy-headers --no-server-header --no-date-header.

uvicorn myapp:app --no-proxy-headers --no-server-header --no-date-header

Questions.

Is it a drop-in replacement?

Yes. The API is FastAPI's and the same 4,489 tests pass. Change the import and keep the rest of your code.

What happens to Starlette?

Starlette is vendored and tuned inside notslowapi; nothing is installed under the starlette name. Code that imports starlette.* directly gets upstream Starlette.

Do the numbers hold across cores?

The numbers on this page are single-core. Measuring multi-core scaling needs a separate client machine.
